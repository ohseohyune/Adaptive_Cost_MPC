AC-MPC Box-Catch 조사 기록

2026-08-03 · 대상: sweep_results/acmpc_box_catch_curriculum_postfix_v4_aabbfix.pt (cond2, 3000 에피소드, 학습 시 성공률 0.841)
평가 조건: full_wide_speed 도메인, seed 1000~1059, online_learning=False

0. 한 줄 요약

박스를 받는 것(catching)은 이미 100% 해결돼 있고, 모든 실패는 5초 안정 유지(hold)에서 발생한다. 그 중 35%는 박스 회전이 원인이며, 회전의 원인인 모서리 파지는 기하학적으로 불가피하다. 회전을 억제하는 유일하게 유효한 수단은 파지력 증가(grasp_compression)였다. 한편 cond2의 PPO 학습은 사실상 작동하지 않고 있다는 사실이 별도로 확인됐다.

1. 확정된 발견

1.1 병목은 catching이 아니라 hold다

120 에피소드 전부가 양쪽 패드 접촉(bilateral contact)에 도달했다. 접촉 실패, 워크스페이스 이탈, 과충격 종료는 0건이다. 모든 실패는 required_hold_s = 5.0초를 timeout_s = 7.0초 안에 연속으로 채우지 못한 것이다. 여유가 약 1.5초뿐이라 한 번의 미끄러짐이 치명적이다.

시사점: 보고 지표를 성공률 단독이 아니라 퍼널로 제시해야 한다 — P(bilateral contact) = 1.00, P(stable hold 5s | contact) = 0.72.

더 많이 위반한 쪽이 성공했다. 성공 에피소드는 접촉 후 ~1초 안에 흔들림을 수렴시키고 나머지 5초를 깨끗하게 간다. 실패는 위반이 에피소드 전체에 흩어져 5초 연속 구간이 만들어지지 않는다. → 처방은 “평균 각속도 낮추기”가 아니라 “접촉 후 정착 시간 단축”이다.

1.4 모서리 파지는 기하학적으로 불가피하다

첫 접촉 시 박스의 앞면이 패드의 앞 모서리와 만난다. 따라서

box_COM_x − pad_center_x = box_half_x + pad_half_x = 5.59 + 4.46 = 10.05 cm

우변에 패드 위치가 없다. 패드를 어디에 두든 접촉점이 함께 이동하므로, 조준 보정으로는 원리적으로 제거할 수 없다. (pad_half_x = 4.46 cm는 선언 두께 0.006 m가 아니라, 패드 geom이 기울어져 장착된 결과다.)

중력 토크 τ = mg·|dx| = 0.5 × 9.81 × 0.10 = 0.49 N·m가 박스를 돌린다.

원리: 모서리 파지(지렛대 10 cm)를 없애는 대신, 접촉 패치의 마찰 토크를 키워 중력 토크를 이긴다. 첫 충돌 피크힘이 변하지 않으므로 ImpactSafe(18 N) 조건은 영향받지 않는다.

주의 2 — 성격: 이것은 미조정된 하이퍼파라미터이지 알고리즘 기여가 아니다. 이력을 보면 원래 0.008이었고 “파지력 부족”을 이유로 0.030으로 올렸으나, 충분히 올리지 않은 상태였다. 논문에는 알고리즘 성과가 아니라 “파지력 하이퍼파라미터가 회전 실패의 지배적 원인이었다”로 서술해야 한다.

주의 3: grasp_compression은 MPC의 압축 천장이므로 actor가 학습으로 도달할 수 없는 영역이다. 즉 성능을 실제로 움직인 지렛대가 정책의 행동 공간 밖에 있었다.

4.2 설계 결함: 회전이 관측에도 보상에도 없다

박스 각속도는 성공 조건에는 포함되지만(strict_angular_ok), observation에도 reward에도 존재하지 않는다. 실패의 35%를 유발하는 요인을 정책이 볼 수 없다. 따라서 현재 구조에서는 “모서리를 피하라”가 학습될 수 없으며, 보상 구조는 오히려 “일찍 닫아 접촉 보너스를 확보하라”(= 모서리 파지)를 유도한다.

5. 신뢰도 경고 — 반드시 확인 필요

오늘 작성한 모든 평가 스크립트에 weight_delta_fraction = 0.0이 들어 있었다.

weights = base × (1 + delta_fraction × residual) 이므로 delta_fraction = 0이면 신경망 출력이 0으로 곱해져 학습된 부분이 완전히 무력화된다. 원인은 평가 하네스를 box_catch_sweep_train.run_one_config(고정 베이스라인 전용 함수)에서 복사한 것이다.

따라서 2~3장의 모든 성능 수치는 cond2(학습된 정책)가 아니라 cond1(고정 phase prior)의 값이다. 재측정 결과 (60시드, weight_delta_fraction = 0.65):
조건성공률각속도 위반residual
cond1 (delta = 0.00, 고정 prior)0.7167 (43/60)0.05110.00000
cond2 (delta = 0.65, 학습됨)0.7500 (45/60)0.04400.04054
차이는 +3.3%p (60시드 중 2개)로 작다. 즉 2~3장의 수치는 실제 cond2보다 약 3%p 낮게 잡혀 있으나 결론의 방향은 바뀌지 않는다. 그리고 이 결과는 4장의 “학습이 거의 일어나지 않았다”를 성능 측면에서도 확증한다 — 3000 에피소드 학습의 순효과가 60시드 중 2개다.

영향받지 않는 결론 (독립 근거가 있음):

  • 4장의 학습 진단 — 실제 훈련 run의 JSON 로그 기반
  • residual 1.8~5.7% 측정 — net을 직접 호출해 delta_fraction을 우회함
  • 1.4의 기하 항등식 — 대수적 유도이며 실험값이 아님

재측정 필요: 2장·3장의 모든 성공률 수치, 1.2의 퍼널 분해.

8. 다음 단계

우선순위 1 — 수치 재측정 (완료 일부)

cond1 vs cond2 비교는 완료됐다 (5장 참조): 0.7167 vs 0.7500, 차이 +3.3%p. 남은 작업은 3장의 grasp_compression 스윕을 cond2에서 재측정하는 것이다. 0.080의 +21.6%p가 cond2에서도 재현되는지, 0.110 절벽 위치가 같은지 확인해야 한다. 2장의 반증 8건은 효과 크기가 크고(붕괴 수준) 방향이 명확하므로 재측정 우선순위가 낮다.

우선순위 2 — 학습이 왜 안 되는지 규명

탐색 노이즈는 원인이 아님이 확인됐으므로, 남은 후보는:

  • maximum_online_actor_delta = 0.02 / maximum_cumulative_actor_delta — 업데이트당 이동량 하드 캡
  • actor learning rate
  • advantage 정규화 / 스케일
  • rollout_size = 16 (PPO 표준의 2~3자릿수 아래)의 gradient 분산

판정 지표는 성공률이 아니라 approximate_KL(1e−5 → 1e−3 이상)과 mean_abs_actor_residual(2~4% → 10% 이상)이어야 한다. phase prior만으로 0.72가 나오므로 성공률로는 학습 여부를 구분할 수 없다.

우선순위 3 — 회전을 관측·보상에 추가

observation에 clip(|ω_box| / 0.15, 0, 2) 1차원, reward에 − w_ang · max(0, |ω_box| − 0.15)² 1항. 단 우선순위 2가 해결된 뒤에 의미가 있다.

우선순위 4 — 기하 재학습

precontact_gap 0.012~0.015 + gap_close_lead_s 0.06 으로 재학습. 목표는 p90 |dx| ≤ 3 cm(평균 ≤ 2 cm)이며, 이는 토크를 절반으로 줄여 grasp_compression을 0.045로 낮추고도 성능을 유지 — 즉 0.110 절벽까지의 마진을 2배로 확보하기 위함이다. 1순위 판정 지표는 접촉률 ≥ 95%다.

9. 부수 확인 사항

  • Ballistic Predictor: 에피소드 시작 시 MuJoCo의 실제 속도로 시드된 뒤 EMA(α=0.35)로 평활화된다. ground truth로 교체해도 차이 없음 (0.717 vs 0.683, McNemar p=0.79). “object state는 관측 가능하다고 가정”으로 서술하면 되며 코드는 유지.
  • HOLD→CAPTURE 강등: 의도적 설계 결정이며(주석에 대안 기각 근거 존재) 성공을 방해할 수 없음이 strict_stable_contact ⇒ both_pads_at_required_force로 증명된다. 단 복구율은 0/9. 부작용: 학습 중 강등 시 exploring = online_learning and phase is not HOLD 때문에 가장 불안정한 순간에 탐색 노이즈가 재활성화된다.
  • Rollout Buffer: rollout_size = 16, truncation bootstrap(next_value = predict_value(observation))과 done 마스킹이 짝을 이루므로 의도적 설계다. 에피소드 경계 교차 여부는 accumulate_rollout_across_episodes 플래그로 별도 실험된 축이다.
  • Phase 이원성: CatchPhase(6개, 제어 상태)와 정책이 관측하는 smoothstep 블렌딩된 소프트 one-hot(4개 control phase, phase_blend_time_s = 0.08)은 다른 것이다. 용어집에는 “Phase / Phase Encoding / Phase Prior” 세 항목으로 분리하고, CatchControlPhase라는 enum 이름은 올리지 않는다.
